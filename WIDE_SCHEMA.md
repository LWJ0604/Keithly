# Flat wide export v1

UTF-8 BOM CSV. Row 1 descriptive bias labels; row 2 machine headers; row 3 onward numeric V/A. No formulas. Ordered family identities are integer trace suffixes `(n)`, never inferred from current similarity. Shared sweep column plus indexed fixed voltage and drain/gate currents are consumed by unchanged research-automation 1.9.1. Source currents are preserved as additional columns. Source complete pointwise CSV remains authoritative.

One file per step / repeat / branch. Means are distinct files in `평균_분석입력`. Names include device, workflow, bias range/ordered list, RAW/AGGREGATE_MEAN, sequence clock, step, repeat, branch and collision-resistant UUID. For long irregular lists, complete values are in provenance. Same-bias distinct family visits keep separate trace identities. No interpolation. Unequal planned grids, mismatched role/channel/setpoint/branch, duplicate or reordered point indices are refused.

Missing/invalid measurements retain planned coordinate rows with blank currents, never zero. Fully empty traces are omitted from the analyzer CSV because the legacy reader rejects them; their complete planned positions and statuses remain in the receipt. If all traces are invalid, only the receipt is emitted, with analysis_ready=false. PARTIAL marks an incomplete/invalid acquisition. This is not a completed rectangular acquisition.

Companion `.provenance.json` includes settings, stable_metadata, acquisition_date, source run IDs/path/point CSV SHA256, point_qc, included/omitted family indices, data_kind, simulation, partial, units/origin, CSV hash and column mapping. Source settings retain condition confirmation and original requested timing. Raw files retain PC timestamps with timezone, statuses and all raw responses. Mean statistics include per-role sample SD (null for n<2), valid/invalid/missing counts and planned indices; sources identify repeats and their immutable point CSV hashes. Same step's exact plan determines contributions; no bias/direction merging.

CSV is written to an exclusive .csv.tmp, flushed/fsynced; the receipt is atomic JSON with fsync; then the CSV is renamed to its unique final name. A failed temporary file is not an analyzer candidate. Existing originals and notes are never rewritten. Source data are saved before export. A new run uses the date of each repeat's PC start; aggregate uses its first contributing repeat date and preserves all source dates in source entries.

The reader does not consume companion JSON or automatically reconstruct device.md from it. Do not equate readable voltage/current columns with full metadata ingestion: light/temperature, instrument integration and compliance settings need separate review in analyzer 1.9.1. CSV avoids its Excel filename light/dark inference. Mean/partial status and n/SD remain authoritative in provenance, even when the old reader calculates its ordinary curves. Do not analyze both legacy nested exports and a new flat representation, or both RAW and means, as independent measurements.


## 1.2.1 metadata review extension
Filename adds decimal `delay<seconds>s` and only explicitly confirmed canonical `light`/`dark`. Delay means the requested host per-point wait, not measured acquisition interval. Analyzer treats these as inferred.
Receipt adds `metadata_review` (ancestor paths/hashes, blockers, scope limits), `filename_metadata`, and `data_file`. `analysis_ready=false` when held. Held wide bytes have extension `.csv.review_required`, not `.csv`; no analyzer input is published. Export result status `metadata_review_required`, `held_files`, `receipts` are separate from acquisition completion. Raw point records remain unchanged. A clean check does not confirm all metadata. No automatic device.md edits or per-file overrides are made.
